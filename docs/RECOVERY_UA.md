# Аварійне відновлення

## Система

1. Перед випробуванням/аварійною заміною **вимкни сервер**; не тримай одночасно два активні примірники з тим самим hostname/IP у мережі.
2. Від'єднай оригінальні системні диски RAID1 (у межах контрольованого вікна) та підключи резервний HDD як внутрішній SATA. Завантажуй через Legacy BIOS; **не перемикай в UEFI**.
3. Перевір: `/` змонтований із UUID `MFS_CLONE`, не `/dev/md0`, GRUB завантажує ядро, мережа/служби працюють.
4. За потреби віднови Development на **окремий** справний диск із `MFS_BACKUP/MAIL_FTP_SERVER_BACKUP/development_snapshots/<дата>`; `MFS_CLONE` не містить цей окремий носій.
5. Датовані системні файлові snapshots допомагають точково повернути файли. Вони **не є гарантовано узгодженими** знімками SQL/контейнерних БД.

## Перевірка

`make verify` перевіряє структуру, UUID та маркери `.sbm-complete.json`; цього недостатньо для підтвердження реального завантаження й відновлення застосунків. Для прийняття потрібний фізичний тест і перевірка служб.
